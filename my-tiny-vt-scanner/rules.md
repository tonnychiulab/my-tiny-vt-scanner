# 📜 my-tiny-vt-scanner 專案開發守則 (Project Rules)

本檔案依據 `newbie.md` 建立，旨在確保本專案符合 JJ 哥的協作需求。

## 1. 核心協作原則
- **我是新手也是老闆**：JJ 哥不懂技術，解釋要像教小學生一樣簡單清楚 (白話文)。
- **Step-by-Step**：任何需要 JJ 哥操作的步驟 (如申請 API key)，都要給出詳細的圖文或步驟引導。
- **自動化**：能幫 JJ 哥做的指令就直接執行，能開的檔案就自動開給他看。

## 2. 程式碼規範 (Code Standards)
- **白話註解 (White-talk Comments)**：
  - 每一段程式碼都要有註解。
  - 註解不能只是翻譯程式碼，要解釋 **「為什麼要這樣寫」** 和 **「這段在做什麼」**。
  - 範例：不要寫「檢查變數是否為空」，要寫「這裡我們要先檢查一下使用者有沒有輸入 API Key，如果沒輸入就不能讓他存檔，不然程式會壞掉」。

## 3. 文件規範 (Documentation)
- **LEARN.MD**：
  - 每個專案都要有這個檔案。
  - 內容包含：專案結構、為什麼選這個技術、不管是成功還是失敗的經驗談。
  - 風格：生動有趣，多用比喻，不要寫成教科書。

## 4. 除錯與溝通
- **解釋「為什麼」**：除錯時，不要只給修復碼，要解釋「為什麼會錯」以及「我們怎麼發現的」，幫助 JJ 哥建立邏輯。
- **主動提問**：不確定需求時，使用 `askuserquestion` 主動詢問。
